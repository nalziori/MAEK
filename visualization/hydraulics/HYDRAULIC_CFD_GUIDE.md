# MAEK 배관 압력·유량 및 고로 CFD 연동

현재 장면은 `Assets/MAEK/Scenes/MAEKHydraulicCFD.unity`입니다.
247개 배관의 압력·유량을 수치 계산하고 3차원 고로 해석과 연결한 연구·시연 모델입니다.
수치는 현장 측정값이 아닙니다. 실제 P&ID·내경·거칠기·운전값을 확보하지 못했으므로
`config.json`에 명시한 가정 조건을 사용합니다. 현장 설계 검증에 사용할 수 없습니다.

## 이번에 계산하는 범위

| 대상 | 계산 및 연결 |
|---|---|
| 배관 247개 | 질량보존 + Darcy–Weisbach 마찰 + 국부손실 + 고도차; 부호가 있는 유량과 노드 절대압 |
| 기체 배관 | 구간별 지정 온도와 이상기체 밀도; 평균압에 따른 밀도 변화, 낮은 Mach 수 가정 |
| 액체 배관 | 지정 밀도·점도의 비압축성 등가유체 |
| 고로 충전층 | 기존 1,496셀 3D Darcy 유한체적 격자의 풍구 압력 응답을 배관 방정식에 포함 |
| 반응·온도 | 계산된 8개 구역별 유입량으로 30초 CO 환원·열수송 재계산; 고로별 별도 결과 |
| 노저부 | 계산된 가스압 → 출선 저항식 → 20,224셀 용선·슬래그·가스 VOF, 12초 새 해석 |
| 표시 | 계산 유량 부호와 유속에 따른 이동 화살표, 배관 수치 패널, 충전층 압력·유속 단면 |

상부의 압력·유량은 **양방향 정상상태 결합**입니다. 12개 가상 풍구를 가까운 8개 CFD 유입 구역에
배정하고, 각 구역의 유입량에 대한 3차원 압력 응답 행렬을 사용합니다. 이 행렬은 별도 경험식이 아니라
기존 Darcy 격자의 단위 유입 해석 8회에서 얻습니다. 계산 후 원래 3차원 격자를 다시 풀어
관망의 인터페이스 압력과 비교합니다. 환상관의 분배와 역방향 유동도 해의 일부입니다.

노저부는 **단방향 경계조건 연결**입니다. 하부 충전층 평균압을 균일한 노저부 가스압으로 가정합니다.
기존 기준 해석의 가스압 150,000 Pa(abs), 출선량 0.0111003435964142 m³/s,
초기 용선·슬래그 정수두를 이용해 등가 출선 저항 R을 정하고,
`Q = sqrt(max(p_gas - p_atmosphere + initial_liquid_head, 0) / R)`로 새 출선량을 계산합니다.
이 Q와 가스압을 새 OpenFOAM 케이스의 경계조건으로 입력합니다.
출선구의 실제 3D 형상이나 운전 데이터를 보정한 저항은 아닙니다.
12초 동안 초기 액체 정수두를 고정하며, 변하는 자유표면 압력을 출선량이나 송풍망으로 되먹임하지 않습니다.

## 실행과 조작

1. Unity 패키지를 가져오거나 기존 프로젝트에서 위 장면을 열고 Play합니다.
2. 오른쪽 패널에서 운전 사례와 배관을 선택합니다. 아래로 스크롤하면 배관 수치가 나옵니다.
3. 배관을 선택하면 시작·끝 절대압 및 게이지압, kg/s, 실제 m³/h, 유속, Re, Mach, 가정 내경을 봅니다.
4. `이 배관으로 검사 카메라 이동`으로 검사 시점을 맞춥니다.

- **Y**: 세 계산 사례 전환. 기준 / 1고로 송풍 압력 60% / 질소 개방·계장공기 소비.
- **V**: 흐름 화살표 표시. 표시 속도는 계산 유속 × 패널의 배속(기본 0.1)입니다.
- **E/L/M**: 조준 배관 선택 / 계통 색상 / 패널 표시.
- **F**, 화살표, Space: 기존 드론 검사와 경로 선택·일시정지.
- **P**: CFD 화면. **H/S**: 노저부·충전층. **1/2**: 고로 선택.
- CFD의 **Shaft pressure / Shaft speed**: 계산된 충전층 압력·겉보기 유속 분포.
- 압력·속도 색상 범위는 두 고로 공통입니다. 계통 식별 색상과 별개입니다.

세 사례는 **실제 수치 해석을 완료한 결과의 재생**입니다. Unity에서 새로운 값을 넣고 OpenFOAM을
실시간으로 푸는 방식은 아닙니다. CFD의 12초와 상부 반응의 30초는 각각의 해석 시간입니다.
관망 화살표는 정상상태 속도장을 표시하며 압력파·난류 입자 궤적이나 과도 유동을 의미하지 않습니다.
CFD 압력 모드의 단위는 Pa(abs), 배관 패널은 kPa(abs)/kPa(g)입니다.
체적유량은 해당 구간 온도·유입측 압력 기준이며 Nm³/h가 아닙니다.

## 운전 가정과 한계

- 내경은 모델 외경의 90%, 거칠기 0.045 mm입니다. 실제 배관 등급을 추정한 값이 아닙니다.
- 기준 송풍기 압력 상승 3,000 Pa, 연소공기 1,800 Pa, 냉각수 펌프 100,000 Pa 등은 시연 입력입니다.
- 펌프는 지정 압력 상승, 기타 장비는 등가 국부손실로 모델링합니다. 실제 펌프곡선·TRT 제어·감압밸브 제어는 미구현입니다.
- 기체는 평균압 이상기체 근사입니다. Mach 0.3을 넘거나 절대압이 양수가 아니면 결과 생성을 실패 처리합니다.
- 마찰계수는 층류 64/Re, 난류 Haaland 근사와 전이 구간 보간입니다. 국부손실계수와 물성은 설정 파일에 있습니다.
- 닫힌 밸브는 유량 0입니다. 압력 기준과 연결되지 않은 밀폐부에는 201,325 Pa(abs)라는 초기압 가정을
  하나씩 부여합니다. 해당 노드는 각 보고서의 `assumed_trapped_pressure_anchors`에 기록됩니다.
- 질소 개방 사례는 공급·회수 압력을 고정한 정상상태 스냅샷입니다. 형상에 있는 유한 용기의 충전·승압 시간은 계산하지 않습니다.
- 계장공기는 대기 시 유량 0이고, 소비 사례에서 액추에이터에 0.0005 kg/s 수요를 줍니다.
  액추에이터 기구 동작은 계산하지 않으며 질소와 공기는 섞이지 않습니다.
- 냉각수의 열전달·열팽창은 계산하지 않습니다. 세정 슬러리는 균질 등가유체이며 고형물 침강·분리를 계산하지 않습니다.
- 열풍의 지정 온도는 1473 K, 레이스웨이 이후 충전층 유입은 1900 K로 가정합니다. 레이스웨이 연소·열수지를 직접 해석하지 않습니다.
- 노저부 VOF의 밀도·점도·표면장력은 기존 등온 기준 해석의 상수 물성을 유지합니다. 연결된 가스압으로 기체 밀도를 다시 계산하는 압축성 VOF는 아닙니다.
- 풍구의 역류나 완전 송풍 정지는 현재 상부 반응 수송 모델에서 지원하지 않아 결과 생성을 중단합니다. 다른 배관의 역방향 흐름은 계산·표시합니다.
- 레이스웨이의 산소가 CO가 된다는 간략 변환으로 코크스에서 추가되는 가스 질량을 계상합니다.
  상부 CO 환원의 조성·분자량·열팽창 변화는 관망 밀도에 다시 반영하지 않습니다.
  관망의 등가유체 질량수지와 상부 반응 해석의 원소수지 검증은 서로 다른 검증입니다.
- 전 고로의 반응·용융·낙하·다상 유동을 완전 양방향 결합한 산업용 CFD-DEM 모델이 아닙니다.

## Blender

`maek_hydraulic_cfd.blend`는 기준 운전 사례로 저장됩니다. 1~289프레임, 24fps입니다.
배관 객체의 `pressure_from_pa_abs`, `pressure_to_pa_abs`, `mass_kg_s`, `velocity_m_s`,
`hydraulic_state` 속성을 확인합니다. 이동 화살표는 기준 계산 유속 × 0.1입니다.
`17_Calculated_pipe_flow`는 배관 흐름, `18_Coupled_CFD_fields`는 새 CFD 결과입니다.
외관 보기에서는 18번을 숨깁니다. 단면을 보려면 12번 원형 외피를 숨기고 13번 단면 외피와
18번을 표시합니다. 14·15번은 이전 참고 결과이므로 숨긴 상태를 유지합니다.
새 충전층 단면은 압력 색상과 x-z면으로 투영한 유속 화살표(유속 × 0.2초)입니다.
Blender에는 세 사례의 수치 데이터를 압축해 보관하며, 생성된 장면의 애니메이션은 기준 사례입니다.
사례 전환은 Unity에서 제공합니다.

## 재계산 및 검증

이 폴더에서 아래 순서로 실행합니다. Python 환경은 기존 `cfd/requirements-cfd.txt`와 동일한
NumPy, SciPy, scikit-image를 사용하며 OpenFOAM Foundation 14가 WSL Ubuntu에 설치되어 있어야 합니다.

```powershell
python build_results.py
powershell -File run_hearth.ps1
python test_hydraulics.py
```

이후 Unity 메뉴 `MAEK/Build hydraulic CFD environment`, Blender의 `build_blender.py`로
장면과 패키지를 갱신합니다. 기존 CFD와 배관 용도 파일은 비교용으로 유지됩니다.

- `pipe_pressure_flow.csv`: 3개 사례 × 247개 배관의 압력·유량.
- `baseline_report.json` 등: 모든 노드의 압력, 내부 유량, 경계조건과 결합 잔차.
- `hearth_run_plan.json`, `hearth_*/coupling_inputs.json`: 실제 OpenFOAM 입력 조건.
- `hearth_coupling_report.json`: 메시, 상분율, 액체 재고 수지, 출선 유량 검증.
- `numerical_tests.log`: 해석해 비교·분기 보존·차단·역류·CFD 응답과 사례별 회귀 검사.
- `unity_hydraulic_report.json`: 결과 교체, 흐름 표시, 고로별 결과, Collider·247개 드론 경로 검사.
- `delivery_summary.json`: 저장 파일과 패키지 내용의 최종 검증.

노드 질량수지 허용오차는 1e-6 kg/s, 운동량 및 결합 압력 잔차는 0.05 Pa입니다.
이는 이산 방정식의 수렴 기준이며 실제 제철소 예측 정확도가 아닙니다.
