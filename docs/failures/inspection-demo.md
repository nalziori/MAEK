# MAEK 드론 시연 연결 실패 기록

## Summary

2026-11-08 점검에서 배관별 카메라가 다음 배관으로 순간 이동했고, 최신 Blender 파일에는
카메라가 남아 있지만 이동 애니메이션은 없었다. 별도의 MAEK 영상 분석 코드를 3D 장면의
실시간 검사 기능으로 오인할 위험도 있었다.

## Root Cause

개별 배관 경로와 CFD 결과를 검증했으나 전경에서 검사 결과 표시까지의 전체 사용자 흐름을
검증하지 않았다. `build_furnace_physics_blender.py`의 카메라 애니메이션 삭제가 후속 파일에
이어졌다. 과거 장면의 기능을 최신 장면에도 있다고 가정한 것이 문제였다.

## Prevention

- 별도 연속 시연 장면과 생성기, 첫 표면 배관 매핑, 요청/이미지 출처 확인.
- 서버가 없거나 응답이 잘못되면 분석 보류; 검출 결과를 미리 준비된 정답으로 대체하지 않음.
- `unity/AGENTS.md`에 재현 명령과 표현 제한을 기록.
- 원래 Blender 파일은 수정하지 않으며 이동 촬영 가능하다고 보고하지 않음.

## Detection

- `tests/test_inspection_bridge.py`: 입력 픽셀 기반 출력, 정답 라벨 무시, 무검출 의미, 좌표 검증.
- `MAEK.Editor.BuildInspectionTour.Verify`: 전 구간 연속 이동, 충돌 정지, 실촬영→HTTP 분석→표면 결과.
- `scripts/check_inspection_harness.py --evidence`: 검증 당시 소스와 현재 소스의 해시 비교.
- `scripts/run_inspection_harness.ps1 -Record`: 실제 녹화·인코딩·디코딩 및 결과 표식 확인.
- `MAEK.Editor.VerifyInspectionPlayMode.Run`: 실제 코루틴/HTTP 경로와 런타임 녹화 24프레임 확인.
  배치 에디터에서 `ScreenCapture.CaptureScreenshot` 호출만으로 파일 생성을 보장할 수 없으므로
  지정 카메라 RenderTexture 캡처를 사용하고 저장된 프레임을 검사한다.

## Evidence

`visualization/inspection_demo/`의 build/integration/record 보고서, 촬영 PNG, analysis JSON,
findings.json, video_report.json. 과거 263개 배관/CFD 검사는 이 통합 시연 검사를 대체하지 않는다.

## 247개 확장에서 확인한 가시성 누락

기존 유틸리티 검사 경로는 배관 중심선 양 끝을 바라봤다. `UTIL-N002`, `UTIL-N003`,
`UTIL-I001`, `UTIL-I002`의 양 끝에서는 배관 대신 조절기·밸브·공급 장치가 먼저 보였다.
충돌 없는 카메라 위치라는 사실만으로 촬영 대상이 보인다고 판단할 수 없었다.
전체 가시성 감사(`visibility_audit.json`)에서 이 네 배관은 기존 시점의 가시성 0,
중간 시점의 가시성 1임을 확인했다.

원래 경로점을 삭제하거나 장비 Collider를 숨기지 않고, 같은 이동 구간의 중간 시점을
추가했다. `sourceIndex`로 원래 경로점의 보존 여부와 추가 촬영점을 구분한다.
`tests/test_inspection_harness.py`는 누락 배관을 중복 배관으로 채워 개수만 맞추는 경우,
끊어진 이동 구간, 건너뛴 원본 경로점, 중복/잘못된 배관 촬영을 거부한다.
실제 촬영 시 대상 배관의 첫 표면이 보이지 않으면 `not_visible`로 기록하고 전체 검사
통과로 인정하지 않는다. 양쪽 실행(에디터/Play 모드)의 촬영·분석 ID를 모두 검사한다.
# 외관 보강 시 보존 규칙 (2026-11-08)

기존 외관은 고로 원통과 얇은 프레임이 드러나 참고 사진보다 지나치게 단순했다.
외장·작업층·보조 배관을 추가하되 이를 위해 원래 경로를 다시 최적화하거나 분석 대상
배관을 옮기면 기존 검증의 의미가 사라진다. `EnhanceSteelworks`는 고정 경로와 촬영 시야를
보호하고 공정 배관 관통을 거부한다. 닫힌 보조 배관은 전체 단위로 수락/거부한다.
`validate_realism_baseline`과 변조 회귀 테스트가 경로 또는 공정 파일의 조용한 변경을 막는다.
실제 공장 배관 설계도나 현장 재질 측정치를 확보했다는 의미는 아니다.


## 외관 조립체의 부분 삭제 방지

최종 렌더에서 새 상부 트러스의 지지대 하나가 경로 보호 검사에서 제외되어 부자연스러운
외팔보가 생긴 것을 발견했다. 배관/비행 충돌 검사만으로 구조물의 외관 완성도를 보장할 수
없다. 상부 트러스는 4개 기둥을 기초 가로보에 연결하고, 완전한 28개 부품 조립체 단위로만
수락하도록 수정했다. 하나라도 부적합하면 전체를 거부하고 다른 배치를 시도한다. 두 고로의
완전한 조립체를 배치하지 못하면 빌드가 실패한다. 빌드마다 같은 3개 카메라로 자동 촬영해
형상 하니스와 렌더 육안 검사를 함께 수행한다.
## 내부 작업 전 Collider 재검사 (2026-11-08)

- 저장된 외관 보강 장면에서 `SERVICE.-97`과 `SERVICE.99`의 외장 기둥이 중앙 통로의
  왼쪽 진입선을 막았다. 기존 드론 경로 검사만으로는 사람의 실내 진입을 검증할 수 없었다.
  `EnhanceSteelworks.Protected`에 실내 중앙 통로와 출입 전후 공간을 추가하고 재생성했다.
- `BF1-A003/000`의 중앙 시선은 공유 접합부에서 `BF1-A002`를 먼저 맞혔다. 기존 실제 촬영
  증거에서는 25개 중 7개 시선이 대상 배관에 닿았다. 저장 장면 검사도 같은 5×5 시선을
  사용하도록 맞췄다. 대상 배관을 가리는 새 구조물을 허용하거나 배관 ID를 바꾼 수정은 아니다.
- 첫 실패 보고서는 `visualization/interior_detail/initial-collider-failures.json`에 보존했다.
  내부 추가 전에 `before-interior-colliders.json`의 10,133개 항목이 통과한 것을 확인했다.
- 내부 첫 렌더에서는 기존 실내 Point Light의 지나치게 넓은 범위와 기본 TextMesh 셰이더로
  과다 노출/벽 너머 글자 표시가 생겼다. 장면 내 조명 범위를 방 크기에 맞추고 인쇄 글자에
  깊이 판정을 적용했다. 글자는 실제 패널/장비 크기에 맞추며 조명 행거는 천장 Raycast로 붙인다.


## 2026-11-09 사고 배관과 가상 배관의 동일시 방지

고로 주변의 임의 배관을 실제 사고 배관처럼 소개하면 산소/BFG, 소결 덕트/고로 배기,
슬러리/산세 배관의 서로 다른 매질·공정·작업 위험을 혼동한다. 사고는 보도상 계통과
확정 범위를 명시하고 미구현 계통을 별도 표시한다. RGB 무검출이나 유량 0으로 작업 허가를
생성하지 않는다. 회귀 검증: `validate_worker_safety`, `tests/test_worker_safety_context.py`,
Unity `MAEKWorkerSafety.Initialize`, 세션 `workPermissionStatus` 근거 검사.


## 2026-11-09 증설 포트·바닥·가림 검증

산소/BFG 및 소결/고로 배기를 이름만 바꿔 대체하지 않는다. 추가 계통은 별도 17구간 그래프로
원본 247개 경로와 ID를 유지한다. 연결 ID가 같아도 실제 렌더 메쉬 끝점이 다르면 실패한다.
첫 새 장면 검사에서 분진함 바닥 관통 5cm 2건과 SINTER-D003 수직관을 D004가 가리는
촬영 위치 1건을 확인했다. 분진함 밑면을 yard 상면 -0.05m에 맞추고 수직관은 측면에서
촬영하도록 변경했다. 충돌 예외를 늘려 통과시키지 않았다. `BuildSupplementaryCircuits.Audit`
가 모든 추가 collider와 전체 장면을 비교하고 공통 포트로 선언한 접합만 예외 처리한다.
방향 그래프의 매질 혼합·고립·막힌 종단은 Python 회귀 테스트가 거부한다.
