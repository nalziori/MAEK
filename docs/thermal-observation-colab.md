# 새 열 관측 데이터 Colab 학습·규칙 비교

이 실행은 정합된 기준/현재 열영상의 관측 변화 분할을 비교한다. 균열·감육 판정이나 현장 안전성을 검증하는 학습은 아니다. 실제 모델 점수는 사용자가 Colab에서 실행한 뒤 생성된다.

## 필요한 파일

실행 묶음은 저장소 옆 `outputs/maek-c/observation-colab-kit-20261108/`에 있다.

- `MAEK_thermal_observation_train_compare.ipynb`: Colab에 여는 노트북.
- `MAEK_thermal_observation_training_bundle.zip`: 새 데이터 1,120쌍, 모델/학습/평가 소스, 고정 비교 프로토콜. 압축을 풀지 않고 업로드한다.
- `comparison_protocol.json`: 학습·평가 조건과 데이터 해시. ZIP에도 포함된다.
- `package_manifest.json`: 전달 파일의 SHA256와 크기.

이전 `thermal-observation-v1-20261108-colab.zip`은 데이터 준비용으로, 이번 학습기·평가기 전체를 포함하지 않는다. 반드시 새 이름의 **training_bundle.zip**을 사용한다. 코드를 따로 복사하거나 Google Drive를 마운트할 필요는 없다.

## 실행 순서

1. [Colab](https://colab.research.google.com/)에서 **파일 → 노트북 업로드**로 `.ipynb`를 연다. 노트북 열기 창의 **업로드** 탭을 이용해도 된다.
2. **런타임 → 런타임 유형 변경 → GPU**를 선택한다. T4가 보이면 선택한다. GPU 제공 여부는 Colab 자원 상황에 따라 달라진다. [공식 안내](https://colab.research.google.com/notebooks/pro.ipynb)
3. 맨 위 코드 셀부터 하나씩 실행한다. 첫 셀에서 실제 CUDA 사용 가능 여부와 GPU 이름을 확인한다. GPU가 없으면 학습을 중단한다.
4. 업로드 셀에서 **`MAEK_thermal_observation_training_bundle.zip`**을 선택한다. 업로드 완료 후 SHA256·전체 파일 해시·분할 개수를 확인한다.
5. **2. Tiny U-Net 30epoch 학습** 셀을 실행한다. epoch별 학습/개발 손실이 출력된다. 640쌍으로 학습하고 개발용 160쌍으로 best.pt를 선택한다. 최대 30분이며 제한에 걸리면 완료로 인정하지 않는다.
6. **3. 동일 입력·오경보 기준으로 비교** 셀을 실행한다. 개발 세트에서 설정을 선택하고, 시험 160쌍·악조건 160쌍을 평가한 뒤 결과 표를 표시한다.
7. **4. 결과 다운로드** 셀을 실행해 `MAEK_observation_results.zip`을 저장한다. `complete = True`인지 확인한다. 오류가 나도 마지막 셀은 실행할 수 있으며 미완료 결과는 `False`로 표시한다.

자동 다운로드는 Colab의 `files.download`를 사용한다. [공식 파일 입출력 예제](https://colab.research.google.com/notebooks/io.ipynb)

다운로드가 시작되지 않으면 Colab 왼쪽 **파일** 패널에서 `/content/MAEK_observation_results.zip`을 찾고 **⋮ → 다운로드**를 누른다. 로컬에 저장된 ZIP을 이 대화에 전달하거나 저장 경로를 알려주면 후속 검증을 할 수 있다. 런타임이 종료되기 전에 결과를 저장한다.

## 같은 기준으로 비교하는 방법

| 항목 | 규칙 | 학습 모델 |
|---|---|---|
| 입력 정보 | 기준·현재 float 온도 | 같은 두 온도의 고정 asinh 3채널 |
| 추론에서 제외 | 참 잡음·깨끗한 영상·정답 위치·원인·물성 | 동일 |
| 방법 | 절대 온도차, 3×3 평활 후 절대 온도차 | 무작위 초기화 소형 U-Net |
| 작은 영역 제거 | 8연결·9픽셀 미만 제거 | 동일 |
| 개발 오경보 제한 | 양성 관측 정답 없는 영상에서 0건 | 동일 |
| 선택 순서 | 관측 영상 재현율 → 픽셀 IoU → 픽셀 재현율 | 동일 |
| 시험 평가 | 선택한 전역 임계값 고정 | 동일 |

픽셀 정답 `255`는 점수에서 제외한다. 연결영역은 정답을 보지 않고 먼저 계산한다. 양성 정답이 없는 영상에서 남은 예측이 GT0 픽셀을 **총9개 이상** 차지하면 영상 오경보로 센다. 정답 양성 영역의 30% 이상을 검출하면 해당 양성 영상을 검출한 것으로 센다. 전부255인 영상은 분모에서 제외하고 수를 보고한다. 양성 정답이 없다는 것은 무결함이나 안전이라는 뜻이 아니다.

고정 후보는 규칙 41개 온도 임계값+OFF, 모델 39개 확률 임계값+OFF다. OFF는 모든 출력을 끄는 후보이며, 선택되면 재현율0인 실패/절충 결과로 표시한다. 개발 세트에서 같은 오경보0건을 맞추어도 시험의 오경보율이 같다고 보장하지 않는다. 시험 결과를 보고 임계값을 바꾸지 않는다.

학습은 30epoch·batch16·seed20261109의 한 번으로 한정한다. AdamW와 cosine 스케줄을 쓰고, 클래스 가중치는 학습 정답에서만 계산한다. 수평/수직 뒤집기도 학습 데이터에만 함께 적용한다. 동일 장면의 5개 변형을 묶어서 2,000회 bootstrap 신뢰구간을 계산한다. 작은 표본의 오경보0건은 실제 오경보 확률0이라는 증거가 아니다.

## 결과 ZIP에서 확인할 파일

- `training/best.pt`: 개발 손실로 선택한 모델.
- `training/history.csv`, `training/training.json`: epoch 손실·시간·GPU·버전·학습 완료 여부·입력 및 소스 해시.
- `comparison/selected.json`: 시험 영상을 열기 전에 저장한 선택 결과.
- `comparison/summary.csv`, `comparison/metrics.json`: 방법별 지표·오경보·신뢰구간과 실제 비교 완료 여부.
- `comparison/`의 개발 후보 표·영상별 지표·예측: 독립 재검산 자료.
- `comparison_protocol.json`, `result_manifest.json`: 고정 조건과 ZIP 내부 파일 해시.

결과가 좋아도 기본 탐지기를 자동 교체하지 않는다. 이 한 번의 합성 실험만으로 현장 균열 탐지·비용 절감·Jetson 성능을 주장하지 않는다.

## 오류가 생겼을 때

- **GPU 없음:** Colab의 GPU 런타임 할당을 확인한다. GPU가 제공되지 않으면 기다렸다 다시 실행한다. CPU로 30epoch 학습을 대체하지 않는다.
- **ZIP 해시 불일치:** 이번에 제공한 새 training_bundle.zip인지 확인한다.
- **이미 폴더가 있음:** 학습 셀을 중복 실행한 경우다. 먼저 마지막 셀로 기존 결과를 저장한다. 점수를 보고 재학습을 반복하지 않는다. 환경 장애로 재시도해야 한다면 새 런타임에서 같은 조건으로 실행하고 실패 기록도 보존한다.
- **학습 미완료/메모리/시간 제한:** 마지막 다운로드 셀로 남은 결과를 저장한다. batch·epoch·임계값을 임의로 바꾼 결과는 동결된 비교에 합치지 않는다.
- **평가 오류:** 학습 결과부터 다운로드한다. 같은 가중치로 오류를 수정해 평가를 이어갈 수 있으며, 곧바로 재학습할 필요는 없다.
- **학습 중 런타임이 완전히 사라짐:** 해당 런타임의 저장 파일을 복구할 수 있다고 보장하지 않는다. 노트북은 외부 저장소 연결 권한을 요청하지 않는다.
