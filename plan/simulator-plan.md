# MAEK 시뮬레이터 구현 계획 (v2: 피드백 반영)

## Context

해커톤(11.09~11.10)에서 "배관 1차 선별 AI"의 타당성을 보여 주려면 학습·평가용 데이터가 필요한데, 실제 점검 데이터는 받을 수 없다.
그래서 가상 배관망에 결함을 현실적인 확률로 넣고, 카메라와 초음파 센서를 소프트웨어로 흉내 내 정답이 붙은 데이터를 만든다.
사전 준비가 허용되므로 시뮬레이터·데이터·베이스라인은 11.08까지 만든다.

저장소 `nalziori/MAEK`: PR #1(문서), PR #2(CI: ruff, pytest, 문서 링크 검사)가 열려 있다.

## 피드백 반영 사항

1. 작업을 서브태스크로 쪼개 서브에이전트에게 맡긴다. 분량에 따라 모델을 나눈다: 단순 작업은 haiku, 보통 작업은 sonnet, 물리 모델·확률 설계처럼 복잡한 작업은 opus.
2. 사용자가 PR을 볼 수 없으므로, 내가 CI 결과를 확인하고 통과하면 머지한다. 실패하면 서브에이전트에게 고치게 한 뒤 다시 확인한다.
3. 시스템의 기능은 3개로 고정한다.

## 핵심 기능 3개

| 기능 | 센서 | 무엇을 찾나 | 출력 |
|---|---|---|---|
| ① 부식 탐지 | 카메라 | 외부 부식, 보온재 밑 부식(CUI)의 겉 징후 | 부식 영역 마스크, 심각도 |
| ② 내부 균열 탐지 | 초음파(사각 탐촉자, 횡파) | 겉에서 안 보이는 내부 균열·파열 | 균열 유무, 추정 높이 |
| ③ 두께 측정 | 초음파(수직 탐촉자, 종파) | 감육, 내부 피팅 | 남은 두께, 부식 속도, 남은 수명, 재측정 시점 |

카메라는 겉만, 초음파는 속만 본다. 초음파는 점 측정이라, ①로 고른 곳과 고위험 위치(엘보·지지대 등)에서만 ②③을 수행한다. 4단계 점검 전략 비교가 세 기능을 묶는다.

## 디렉터리 구조

```
config/default.yaml        # 모든 파라미터 + source 또는 assumption 표시
maek/
  params.py                # 설정 로드·검증, 발표용 파라미터 표 생성
  network.py               # 가상 배관망 100km + 결함 정답
  camera/jobs.py           # ① 렌더 작업 목록(JSON, 렌더러와의 계약)
  camera/composite2d.py    # ① 기본 렌더러: 부식 패치 합성 + 마스크(YOLO-seg 형식)
  ut.py                    # ②③ A-scan 생성(수직·사각 탐촉자) + 베이스라인 판정
  pod.py                   # hit/miss POD 곡선, a90
  strategy.py              # 기존 방식 vs AI 선별 방식 몬테카를로
  cli.py                   # python -m maek <명령>
tests/
data/                      # 생성물, git 제외
requirements.txt           # numpy, pandas, pyyaml (+ 선택: matplotlib, opencv-python)
```

## 예산 (세션 전체 70달러)

- opus는 물리·확률 설계가 핵심인 T3(배관망)과 T4(초음파)에만 쓴다. T8(전략 비교)은 sonnet으로 내리고, 막히면 그때만 opus로 올린다.
- 서브에이전트 수를 줄이려고 작은 작업은 묶는다: T1+T2(sonnet 1개), T5+T6(sonnet 1개), T7+T11(sonnet 1개), T9(haiku). T0과 T10(스크립트 실행)은 내가 직접 한다.
- 서브에이전트에게는 필요한 파일과 인터페이스만 넘기고, 결과 보고는 짧게 받는다. 큰 로그·데이터는 대화에 붙이지 않는다.
- 데이터 생성 규모는 먼저 작게(예: 10km, 이미지 300장, A-scan 2,000개) 돌려 확인한 뒤 전체 규모로 한 번만 생성한다.
- 정확한 사용 금액은 이 세션에서 실시간으로 볼 수 없다. 단계마다 남은 작업을 점검하고, 예산을 넘길 것 같으면 그 자리에서 멈추고 휴대폰으로 알린다. 우선순위는 ③ 두께 → ② 균열 → ① 부식 → 전략 비교 → 리소스 점검 순으로, 뒤쪽부터 줄인다.

## 진행 방식

날짜에 묶지 않고 의존 순서대로 끝까지 진행한다: T0 → T1 → T2 → (T3, T4) → (T5, T6) → (T7, T8) → (T10, T11) → T9. 단계가 끝날 때마다 휴대폰으로 알린다.

## 산출물 저장

- **GitHub 저장소:** 코드, 테스트, 설정, 작은 샘플 데이터(수 MB 이하), 결과 문서.
- **구글 드라이브:** 전체 데이터셋, 이미지, 큰 결과 파일 등 저장소에 올리기 어려운 것. 이 세션에는 구글 드라이브 연결이 없다. https://claude.ai/customize/connectors 에서 Google Drive를 연결한 뒤 새 세션에서 올려야 한다.
- **드라이브 연결 전 임시 보관:** GitHub Release 첨부 파일(파일당 2GB 이하)로 올려 두고, 드라이브가 연결되면 옮긴다. 데이터는 seed로 다시 만들 수 있으므로 재생성 명령도 함께 기록한다.

## 탑재 리소스 기준 (T11)

- 탑재 대상은 ① 부식 탐지(카메라 영상, 실시간 필요). ②③ 초음파 판정은 신호가 작아 탑재 부담이 작지만 함께 측정한다.
- 측정: 모델 파일 크기, 최대 메모리, 프레임·신호당 지연, 초당 처리량. CPU 4스레드·메모리 제한으로 소형 보드를 근사하고, 실제 보드 수치가 아님을 명시한다.
- 판정 기준(가정): 영상 5fps 이상, 메모리 2GB 이하. 못 맞추면 해상도 축소, 경량 모델, 지상 처리(드론은 촬영만)로 대안을 제시한다.

## 테스트 기준

- `network`: 같은 seed → 같은 결과, 총 길이 100km, CUI는 보온재 있는 구간에만, 외부 결함만 `visible_external`, 엘보에 유동가속부식이 통계적으로 더 많음.
- `ut` ③: 결함 없는 신호에서 추정 두께가 정답 ±0.1mm 안, 감육하면 뒷면 반사가 앞당겨짐.
- `ut` ②: 사각 탐촉자는 균열이 있을 때만 에코, 균열이 높을수록 진폭 증가.
- `camera` ①: 마스크 면적이 결함 면적과 일치, 같은 seed → 같은 이미지.
- `pod`: 알려진 로지스틱에서 뽑은 데이터로 계수 복원.
- `strategy`: 완벽한 선별 모델이면 AI 방식 발견율 ≥ 기존 방식이고 초음파 지점 수는 감소.
- `params`: 모든 파라미터에 `source` 또는 `assumption`이 있음.

## 확인 방법

1. PR마다 CI 통과를 확인하고 머지.
2. main에서 `python -m maek network`, `ut`, `camera-jobs`, `render2d`, `strategy`, `params-table`을 순서대로 실행해 `data/` 산출물 확인.
3. `docs/results.md`에 세 기능의 성능, POD 곡선(a90), 전략 비교 비율이 기록됐는지 확인.
4. 단계가 끝날 때마다 휴대폰으로 진행 상황 알림.

## GPU

이 계획(시뮬레이터, 데이터, 베이스라인, 리소스 점검)은 CPU로 충분하다. GPU는 대회에서 YOLO-seg를 학습할 때 팀 GPU나 Colab에서 쓰며, T7에서 학습 스크립트(`scripts/train_yolo_seg.py`)만 준비해 둔다.

## 팀이 정할 것

- 카메라 렌더러: 기본은 2D 합성. Unity·Blender를 쓸 팀원이 있으면 렌더 작업 JSON을 읽는 렌더러를 따로 붙인다.
- 비전 모델 학습(YOLO-seg)은 팀 GPU나 Colab에서. 이 계획은 데이터·라벨·베이스라인까지 맡는다.
