# 3대 기능 베이스라인 평가 결과

모든 수치는 **시뮬레이터 합성 데이터**에서 고정 시드(`--seed 0`)로 얻은 값이며, 실제 현장 데이터가 아닙니다.
아래 구현은 대부분 **고전(규칙 기반) 베이스라인**이고, 해커톤에서 학습 모델로 개선할 출발점입니다.
③ 피트 검출만 작은 학습 분류기(DR 데이터로 학습)를 씁니다("③ 어려운 조건의 피팅 탐지 개선" 절).

## 재현 명령

```bash
export OMP_NUM_THREADS=1
python -m maek evaluate --out data/eval            # 이 문서의 표 (이미지 300장 x 2조건, UT 3000개 x 2조건, 전략 10회, 피트 방법 비교)
python -m maek onboard  --out data/eval            # docs/onboard-resources.md
python -m maek params-table --write                # docs/params.md
python -m maek.pit --write                         # 학습 피트 분류기 가중치 maek/pit_model.json 재생성 (약 1분)
```

- 크기 설정은 `config/default.yaml`의 `eval.*` (`n_camera=300`, `n_ut=3000`, 이미지 640 px, 모두 `assumption: true`).
- 결과 파일: `data/eval/camera_metrics.csv`, `ut_metrics.csv`, `pod.csv`, `strategy_crack.csv`, `results_tables.md`,
  피트 탐지용 `pit_ablation.csv`, `pit_factors.csv`, `pit_dr_validation.csv`, `pit_dr_coverage.csv`, `pit_pod.csv`.
- 소요 시간: 약 9분 (CPU 1코어, 단일 스레드 설정; 피트 방법 비교가 약 5분).

## 평가 방식

- **train / shifted**: 같은 시뮬레이터에서 조건만 다르게 만든 두 데이터셋입니다.
  - 카메라 shifted: 조명 0.25~0.6배(어두움), 분진 0.3~0.7, 증기 0.3~0.8, 블러 1.5~3.5 px, 센서 노이즈 0.03~0.08
    (train은 0.5~1.5배, 0~0.4, 0~0.5, 0~2 px, 0~0.04). `camera.shifted_*` 파라미터.
  - UT shifted: 온도 100~175 C(고온 배관), 접촉 0.3~0.7(불량 접촉), 노이즈 3배 (`ut.dataset.shifted_*`).
  - 온도 보정: 분석은 실제 온도가 아니라 **측정 온도 = 실제 + 오차**로 음속을 보정합니다. 오차 표준편차는 train 2 C, shifted 15 C
    (`ut.dataset.*_temp_meas_error_c`, 가정값). `ut.temp_compensation: none`이면 20 C로 가정해 보정하지 않습니다.
  - 베이스라인의 임계값은 두 조건 모두에서 같게 고정했으며 shifted로 재조정하지 않았습니다.
- **① 부식 분할기** (`maek/camera/segment.py`): 평균 밝기 정규화 후 HSV에서 색상 5~40도, 채도 >= 0.35, 명도 >= 0.12를
  녹으로 판정하고 3x3 침식-팽창으로 잡음 제거. 클래스는 corrosion(1)만 평가합니다.
  - 픽셀 IoU: 전체 이미지 합산(교집합 / 합집합). 이미지 검출: 예측 30 px 이상. 오경보: 정답에 부식 픽셀이 없는데 검출.
  - 결함 단위 hit: 결함 위치 주변 정답 픽셀의 30% 이상이 예측되면 hit. 크기는 결함 면적(cm2).
- **② 균열**: 사각 UT 코너트랩 에코 게이트 검출(`ut.detect_crack`). 크기는 균열 높이(mm).
- **③ 두께**: 직진 UT 뒷면 에코 열의 간격(`ut.estimate_thickness`)으로 공칭 두께를 추정해 MAE와 +-0.1/+-0.5 mm 이내 비율을 봅니다.
  피팅이 있어도 벽 두께를 읽도록 에코 열 간격을 점수화합니다.
  직진 UT A-scan은 같은 위치에서 16번 쏜 신호의 평균입니다(`ut.n_avg`).
  피트 검출은 기본 검출기 `ut.detect_pit`(정합 필터 + 저면 에코 차감 + CFAR 특징의 학습 MLP, CFAR 게이트)이 판정하고 크기는 피트 깊이(mm)입니다.
  예전 규칙(`ut.min_thickness`가 공칭보다 0.3 mm 이상 얇으면 hit)과의 비교는 아래 "③ 어려운 조건의 피팅 탐지 개선"에 있습니다.
- **POD**: `maek.pod`의 로지스틱 모델(ln 크기)을 hit/miss에 최대우도로 적합, a90 = POD 90% 크기.
  대괄호 안은 부트스트랩 300회의 95% 백분위수(a90/95 근사, 일측 상한).

## 해석과 한계 (솔직한 메모)

- **train -> shifted 하락이 큽니다.** ① 픽셀 IoU 0.82 -> 0.26, 결함 단위 hit율 0.99 -> 0.31, 이미지 검출률 1.00 -> 0.76.
  어둡고 뿌연 영상에서 색상 임계값이 녹 색을 놓치는 전형적인 사례이며, 조건에 맞게 임계값을 다시 잡거나 학습 모델로
  개선해야 합니다. shifted에서 오경보는 2% 수준이라 놓침이 문제입니다.
- ② 균열은 train에서 전부 검출(오경보 0)이라 합성 조건이 베이스라인에 쉽다는 뜻이기도 합니다(최소 균열 높이 0.15 mm 이상).
  이 수치를 실제 성능으로 읽으면 안 됩니다. shifted에서는 검출률 0.91, a90 1.22 mm [상한 1.34 mm]로 나빠집니다.
- ③ 1회 측정에서는 shifted 두께 MAE가 0.43 mm로 나빠졌습니다(정확히 맞거나 에코 간격을 잘못 잡아 크게 틀리는 이중 모드).
  16회 평균으로 0.02 mm가 됐습니다. 피트 검출은 예전 규칙에서 shifted 0.05로 무너졌고, 원인을 요인별로 나눠 보고 고친 결과가
  아래 절입니다(shifted 0.89, 오경보 0.7%). 원인은 노이즈 3배가 가장 크고, 측정 온도 오차는 영향이 없었습니다.
- 모든 임계값/가정은 `assumption: true` 파라미터이며 현장 보정이 없습니다. POD 곡선도 시뮬레이터 안에서의 값입니다.
- 이 베이스라인들은 **해커톤에서 학습 모델(YOLO-seg 분할기, 1D-CNN 등)로 개선할 기준선**입니다.
  개선 여부는 위 표의 같은 지표(특히 shifted 열)로 비교합니다.

## ③ 어려운 조건의 피팅 탐지 개선

예전 규칙(`ut.min_thickness`)은 shifted에서 내부 피팅을 거의 놓쳤습니다(검출률 0.045).
원인을 요인별로 나눠 보고, 현장에서도 할 수 있는 방법만 골라 비교한 뒤 기본 검출기를 바꿨습니다.

- 코드: `maek/pit.py`. 기본 진입점은 `ut.detect_pit(cfg, signal, wall_nominal_mm, temp_c) -> {found, score, depth_est_mm}`입니다.
  `ut.min_thickness`와 `ut.estimate_thickness`는 그대로 있습니다.
- 원칙: shifted 데이터는 학습, 임계값, 방법 선택 어디에도 쓰지 않았습니다. 학습과 임계값은 도메인 랜덤화(DR) 데이터(별도 시드)로,
  방법 선택은 또 다른 시드의 DR 검증 세트로 했습니다. shifted는 마지막 시험에만 씁니다.
- 모든 표는 `python -m maek evaluate`가 만듭니다(UT 3000개, 시드 0, 피트 936개, 무결함 2064개; 요인 분리는 1000개; DR 검증은 평균 횟수별 2000개).

### 1. 원인 진단: shifted 요인을 하나씩만 적용

| 조건 | 기존 규칙(min_thickness), 평균 1회 | 학습 MLP (1~4 특징) + CFAR 게이트, 평균 1회 | 기존 규칙(min_thickness), 평균 16회 | 학습 MLP (1~4 특징) + CFAR 게이트, 평균 16회 |
|---|---|---|---|---|
| train | 0.914 (0.000) | 1.000 (0.000) | 0.901 (0.000) | 1.000 (0.003) |
| 노이즈 3배만 | 0.339 (0.000) | 0.802 (0.000) | 0.744 (0.000) | 0.872 (0.013) |
| 접촉 0.3~0.7만 | 0.709 (0.000) | 0.981 (0.000) | 0.911 (0.000) | 1.000 (0.003) |
| 고온 100~175 C + 측정 오차 15 C만 | 0.923 (0.000) | 1.000 (0.000) | 0.904 (0.000) | 1.000 (0.003) |
| 노이즈 + 접촉 | 0.035 (0.000) | 0.671 (0.001) | 0.652 (0.000) | 0.869 (0.015) |
| shifted 전체 | 0.038 (0.000) | 0.668 (0.000) | 0.655 (0.000) | 0.879 (0.013) |

- **노이즈 3배가 가장 큰 원인**입니다. 예전 규칙에서 노이즈만 3배로 해도 0.91 -> 0.34로 떨어집니다.
- 접촉 0.3~0.7만 바꾸면 0.71입니다. 접촉은 피트 에코와 결정립 산란을 같이 줄이지만 전자 노이즈는 그대로라 신호 대 잡음 비가 떨어집니다.
- 고온 100~175 C와 측정 온도 오차 15 C는 영향이 없습니다(0.92). 음속 보정이 약 0.2% 틀릴 뿐이라 깊이 오차가 0.02 mm 이하입니다.
- 노이즈와 접촉이 겹치면 피트 에코 대 잡음 비가 곱으로 줄어 0.04가 되고, 이것이 shifted 전체(0.04)와 같습니다.
- 예전 규칙은 "잡음 MAD의 6배와 가장 큰 에코의 15% 중 큰 값"을 넘는 첫 에코를 찾습니다. shifted에서 잡음 문턱은 약 0.36인데
  피트 에코는 접촉 x 피트 면적 비율 = 0.03~0.35라 거의 넘지 못합니다.

### 2. 비교한 방법

1. **정합 필터**: 알고 있는 탐촉자 펄스와 상관을 취한 뒤 포락선을 봅니다. 전자(백색) 노이즈가 약 2.7배 줄어듭니다.
   결정립 산란은 탐촉자 대역 안에 있어 줄지 않습니다.
2. **코히어런트 평균**: 같은 위치에서 N번 쏜 A-scan을 평균합니다(`ut.n_avg`, `ut.simulate_straight(..., n_avg=N)`).
   샷마다 독립인 전자 노이즈는 1/sqrt(N)로 줄고, 접촉과 결정립 산란(탐촉자 아래 조직이 같음)은 공유되어 줄지 않습니다.
   n_avg=1이면 예전 신호와 똑같습니다(테스트로 확인). 추가 샷은 별도 난수열을 써서 형상·라벨·사각 UT 신호도 그대로입니다.
3. **접촉 정규화**: 에코 진폭을 첫 저면 에코로 나눕니다(접촉은 모든 에코를 같은 비율로 줄임).
   그늘(shadow) 단서는 피트가 빔 일부를 가려 저면 에코가 약해지는 것을 봅니다. 접촉과 구분하려면 기준 에코가 필요해 계면 에코를 썼습니다.
   이 시뮬레이터에서는 접촉이 계면 에코도 같은 비율로 줄여서 맞지만, 실제 접촉층에서는 계면 에코가 오히려 커질 수 있어 현장 근거가 약합니다.
   그래서 그늘은 참고(상한)로만 보고 기본값에서 뺐습니다. 저면 에코 열 감쇠 변화도 특징에 넣었지만 이 시뮬레이터에서는 피트가 감쇠를 바꾸지 않아 정보가 거의 없습니다.
4. **CFAR 적응 임계값**: 잡음 크기를 신호 끝 1/4(링다운 뒤, 아직 남은 저면 에코 위치는 제외)의 포락선 중앙값으로 추정하고,
   임계값 = sqrt(2 ln(셀 수 / Pfa)) + 0.75 (Pfa 0.002, 0.75는 잡음 추정 오차 여유)로 둡니다. 계면 에코 앞 구간은 결정립 산란이 없고 약 30샘플뿐이라
   피트 창의 잡음을 대표하지 못해 끝 구간을 씁니다.
   함께 **저면 에코 차감**을 넣었습니다. 에코 열 간격으로 저면 에코 시각을 찾고, 알려진 펄스 응답으로 저면 에코를 뺀 뒤 그 앞의 모든 시각을
   조건부 통계(차감 후 잡음으로 정규화)로 봅니다. 그래서 저면 에코와 겹치는 얕은 피트(예: 6 mm 벽의 0.5 mm 피트)도 찾습니다.
5. **학습 분류기**: 1~4에서 만든 특징 7개(피트 창 최대 CFAR 신호대잡음비, 피트 에코 2번째까지 합친 값, 저면 대비 상대 진폭, 저면 에코 신호대잡음비,
   에코 열 감쇠 변화, 3 sigma 초과 비율, 깊이/두께)로 작은 MLP(은닉 16, numpy, Adam)를 학습합니다. 학습은 DR 4000개, 임계값은 무결함 DR 6000개로
   평균 횟수별 x 저면 신호대잡음비 2대역마다 오경보 0.5%가 되게 정합니다(대역별로 정하지 않으면 저신호 구간에 오경보가 몰렸습니다).
   DR 범위: 노이즈 0.5~4배(로그 균등), 접촉 0.2~1.0, 온도 -10~220 C(배관망 매질 온도 전체), 측정 온도 오차 0~20 C, 평균 1/4/16회.
   이 범위는 shifted를 포함하도록 넓게 잡은 가정입니다. 마지막으로 **CFAR 게이트**를 둡니다. 분류기가 피트라고 해도 피트 창에서 가장 큰 에코가
   CFAR 설계 임계값(여유 0)을 넘을 때만 인정합니다(이유는 4절).

### 6. 비용

- 측정 시간: 16회 평균은 측정점당 (16 - 1) / PRF = 0.15 s 늘어납니다(PRF 100 Hz 가정, `ut.prf_hz`, `ut.avg_extra_time_s`).
  측정점당 작업 시간 0.5 h(`strategy.ut_hours_per_point`)에 비하면 작습니다. 다만 드론 접촉 UT라면 그 0.15 s 동안 접촉이 유지되어야 합니다.
- 계산: A-scan 1개에 약 1.8 ms(학습 분류기), 1.3 ms(규칙)입니다(CPU 1코어; 정합 필터 FFT, 에코 간격, MLP).
- 학습: DR 1만 개 생성과 특징 계산에 약 50초. 가중치는 `maek/pit_model.json`(약 5 KB)으로 함께 배포합니다. UT 물리나 DR 파라미터를 바꾸면
  해시가 달라져 처음 호출할 때 다시 학습하고, `python -m maek.pit --write`로 파일을 갱신합니다.
- 예전 기본값 대비 두께 MAE도 좋아졌습니다(shifted 0.434 -> 0.020 mm). 평균으로 에코 간격을 잘못 잡는 경우가 사라졌기 때문입니다.

### 7. 한계

- 남은 놓침(shifted 11%)은 결정립 산란 한계입니다. 평균으로 줄지 않으므로 탐촉자를 조금씩 옮기며 평균(공간 평균)하거나
  분할 스펙트럼 처리 같은 방법이 다음 후보입니다(이번에는 구현하지 않음).
- DR 범위는 가정이고 shifted를 포함합니다. shifted 자체는 보지 않았지만 범위 선택이 결과에 영향을 줍니다.
  범위를 벗어나면 검출 이득은 보장되지 않고, 오경보만 CFAR 게이트로 약 2% 아래로 묶입니다(4절 표).
- 학습 분류기는 시뮬레이터 결함 분포(피트 면적 비율 0.1~0.5)를 배웁니다. 이보다 작은 피트에는 규칙(`mf_cfar`)보다 불리할 수 있습니다.
- 평균 16회에서 학습 분류기의 오경보(0.7%, 무결함 2064개 중 14개)는 규칙(0.0%)보다 높습니다.
  요인 분리 표(1000개)에서 노이즈가 큰 조건은 1.3~1.5%까지 올라갑니다. 오경보를 더 줄여야 하면 `mf_cfar`를 쓰면 됩니다.
- 시뮬레이터 단순화: 피트 에코와 저면 에코는 독립 펄스(모드 변환, 산란 형상, 빔 퍼짐 없음), 접촉은 모든 에코를 같은 비율로 줄임,
  평균하는 동안 접촉이 변하지 않음, 결정립 산란이 깊이에 따라 약해지지 않음. 실제 데이터로 다시 확인해야 합니다.
- POD를 깊이 하나로만 나타내면 shifted처럼 면적 비율과 접촉이 좌우하는 경우를 잘 설명하지 못합니다.

## 전략 개선: 위험 순위 기반 균열 UT (v2 기준 기록)

기준 전략의 고정 측정점은 두께용(수직 탐촉자)이라 균열을 찾지 못합니다(검출률 0). 기존 AI 트리아지는 용접부를 무작위(5%)로, 고피해 엘보를 모두 사각 UT로 쟀지만 치명 균열을 거의 못 찾았습니다.
새 모드(`strategy.crack_ut_mode: risk_ranked`)는 금속 배관의 용접/엘보 위치를
**점수 = (경년/기준)^지수 x 피해등급(매질) x 형상 가중치(용접 0.6 > 엘보 0.3)** 로 순위를 매겨,
기준 전략 고정 UT 점 수의 `crack_ut_budget_frac`(0.30) 만큼만 상위부터 측정합니다.
(`crack_ut_mode: random`으로 기존 동작 유지.)

| 100 km x 10회 평균 (시드 0) | 치명 균열 검출률 | 평균 UT 점 수 |
|---|---|---|
| 기준(고정 CML) | 0.000 | 3821 |
| AI 기존(random) | 0.027 | 2389 |
| AI 위험순위(risk_ranked) | 0.149 | 3031 |

AI 총 UT 점 수는 기준 전략보다 적게 유지됩니다(약 79%). 다만 절대 수준(약 15%)은 여전히 낮은데, 사각 UT POD 파라미터
(`strategy.pod.ut_angle`, 균열 깊이 mm 기준)가 가정값이고 시뮬레이션 균열이 대부분 작기 때문입니다.
예산 비율 0.2/0.3/0.4/0.5에서 검출률은 약 0.10/0.15/0.22/0.27, UT 점 수는 기준의 69/79/89/99%였습니다.
비용·정확도 균형에 맞는 비율은 현장 협의가 필요합니다(비용은 `python -m maek strategy`로 확인).

**v2에서 바뀐 점.** v2(비용 x0.27)는 보온 배관도 드론이 초음파로 잴 수 있다고 봤고, 보온재 해체 비용이 없었습니다. v3는 다음을 반영합니다.
- 보온 배관 초음파는 사람이 보온재를 열어야 합니다. 높은 곳이면 비계(또는 고소작업차)가 필요합니다.
- 드론+AI는 열화상으로 젖은 보온재를 찾고 PEC로 보온재 위에서 먼저 잽니다.
- 스팀 트랩은 세 방식 모두 사람이 전수 점검합니다.
- 초음파 1점 비용의 인건비 이중 계산을 없앴습니다.

비용 내역과 손익분기는 [비용 모델](cost-model.md)에 있습니다.

**드론만으로 얻는 것.** 비보온 가공 배관의 비계가 사라져 비용 x0.70, 소요 일수 x0.78입니다. 영상 판독으로 외부 징후를 더 봐서 발견율이 0.19에서 0.27로 오르지만, 측정점이 같아 감육·균열·피팅은 그대로입니다.

**AI가 더하는 것.** 위험 지점(엘보, 용접부, 지지대)과 열화상이 찾은 젖은 구간에 측정을 몰아, 발견율이 0.27에서 0.59로 오르고 놓친 고피해 결함이 33개에서 20개로 줄어듭니다. 측정 지점과 보온재 해체는 오히려 14~17% 적습니다.

**가장 큰 변수는 높은 곳 접근입니다.** 고소작업차로 효율적으로 접근하면 드론+AI의 비용은 사람+비계와 비슷해집니다(x1.02, 10회). 발견율 약 3배는 그대로입니다. 가정을 15가지로 바꿔 본 결과는 [가정 흔들기](robustness.md)에 있습니다.

**증기 계통 대표 시나리오**(20 km)는 [증기 시나리오](steam-scenario.md)에 있습니다. 보온 배관이 95%라 드론만으로는 비용이 거의 줄지 않고(x0.97), 드론+AI는 x0.83에 위험 결함 발견율 0.15에서 0.59입니다.

**내부 피팅**은 젖는 자리 스캔으로 0.040에서 0.054로만 오릅니다. 병목은 덮는 길이입니다. 회로 단위 판정으로 목표를 바꾸는 방법은 [피팅 전략](pitting-strategy.md)에 있습니다.

**주의.** 단가, 작업 속도, 인원, 영상 판독 POD, 드론 접촉 UT POD는 가정값(`assumption: true`)입니다. 피팅 UT POD와 열화상 POD는 시뮬레이터 적합값이지만 역시 현장 검증 전입니다. 소요 일수는 팀 수와 하루 작업 시간으로 나누고 단계를 순서대로 더한 값입니다.

## 포항·광양 배관 길이 시나리오 (비계 기준)

공개 자료로 추정한 포항·광양 배관 길이와 매질 구성([매질 대응](pipe-length-mapping.md))을 넣어 같은 비교를 돌렸습니다. 실제 설비 목록이 아닙니다. 모두 `OMP_NUM_THREADS=1`, `--seed 1`이고, 높은 곳은 비계로 접근합니다(`strategy.human_elevated_access=scaffold`).

예: `python -m maek strategy --scenario pohang_base --runs 10 --seed 1` (구성 효과만 볼 때 `--total-km 100`)

**구성 효과** (100 km × 20회, 괄호는 사람+비계 대비)

| 매질 구성 | 위험 결함 발견율 (사람 → 드론+AI) | CUI | 유동가속부식 감육 | 놓친 고피해 결함 (개) | 비용 (억 원) | 소요 일수 |

| 포항 base | 0.171 → 0.582 (x3.40) | 0.228 → 0.669 | 0.020 → 0.628 | 10.0 → 4.9 | 36.1 → 21.5 (x0.60) | x0.67 |
| 광양 base | 0.169 → 0.588 (x3.48) | 0.217 → 0.660 | 0.028 → 0.626 | 9.1 → 4.2 | 36.1 → 21.5 (x0.59) | x0.67 |

|---|---|---|---|---|---|---|

**읽는 법**
- **발견율 약 3배는 그대로입니다.** 매질 구성, 길이, 대응 가정을 바꿔도 x3.2~x3.5입니다. 기본망(x3.06)보다 조금 높은 것은 드론+AI가 비슷하고(0.58~0.59) 사람 방식이 낮기 때문입니다(0.19 → 0.17).
- **놓친 고피해 결함의 절대 개수는 기본망보다 훨씬 적습니다.** 100 km당 39.6개가 포항 10.0개, 광양 9.1개입니다. 피해등급 5 매질이 30%에서 약 8%로 줄었기 때문입니다. 그래서 개수 대신 비율로 읽습니다. 드론+AI는 어느 시나리오에서도 약 절반(x0.41~x0.49)으로 줄입니다.
- **길이를 줄이면 고위험 비율이 올라갑니다.** JSON은 가스 배관 길이를 부지 폭과 고로 수로 따로 정합니다. 그래서 p가 작아 총 길이가 짧으면 피해등급 5 비율이 올라갑니다(광양 7.6% → 9.1%). 광양 fixed_topology(828 km)가 base(1,065 km)보다 놓친 고피해 결함이 많은 이유입니다(106.2개, 94.6개).
- **비용 x0.59는 비계 가정입니다.** 기본망(x0.54)보다 이점이 조금 작습니다. 고소작업차로 접근하면 기본망에서 x1.02였습니다([비용 모델](cost-model.md)). 포항·광양의 고소작업차 결과는 아직 없습니다.
- **목표 대비 실제 매질 비율 차이**는 13개 실행 모두 최대 0.7%p 이하입니다. 50 m 구간 무작위 배정으로 생기는 차이이며, 결과에 영향을 줄 크기가 아닙니다.
- 원본 CSV와 실행별 요약은 공유 드라이브 `agents-shared/2026-11-06_agy_pohang-gwangyang/`에 있습니다(실행: Antigravity).

## 학습형 YOLO-seg (Colab / GPU)

`scripts/train_yolo_seg.py`는 렌더링한 `dataset.yaml`을 Ultralytics YOLO-seg로 학습/평가하는 독립 스크립트입니다
(core 의존성이 아니며 CI/pytest 대상 아님; `pip install ultralytics` 필요).

```bash
# 1) 데이터 생성 (로컬 또는 Colab)
python -m maek camera-jobs --n 2000 --out data/ && python -m maek render2d --out data/
# 2) 학습 / 검증 / 내보내기 / 보드 벤치마크
python scripts/train_yolo_seg.py train  --data data/camera/dataset.yaml --epochs 50 --imgsz 640
python scripts/train_yolo_seg.py val    --data data/camera/dataset.yaml --weights runs/segment/maek/weights/best.pt
python scripts/train_yolo_seg.py export --weights runs/segment/maek/weights/best.pt --format onnx --imgsz 320
python scripts/train_yolo_seg.py benchmark --weights runs/segment/maek/weights/best.pt --data data/camera/dataset.yaml
```

Colab에서는 런타임 유형을 GPU로 바꾸고 저장소를 `git clone`한 뒤 `pip install pyyaml pillow pandas numpy ultralytics`
후 위 명령을 실행하면 됩니다. shifted 조건 성능은 `make_jobs(..., condition="shifted")`로 별도 데이터셋을 렌더링해 `val --data`에
넘겨 측정합니다. 클래스는 0 corrosion, 1 cui_sign, 2 leak_stain입니다. 이 환경에서는 학습을 실행하지 못했으므로 학습 모델 수치는 없습니다.
탑재 자원 측정은 [onboard-resources.md](onboard-resources.md)를 참고하세요.
