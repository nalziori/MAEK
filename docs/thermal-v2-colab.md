# v2 기준선·추가 학습·처음 학습 Colab 실행 안내

이 노트북은 MAEK **합성 열적 관측** 모델을 비교한다. 균열/감육 확정 정확도, 실제 센서 성능, NDT 비용 절감을 검증한 결과가 아니다. 기존 모델과 v1/v2 데이터는 보존한다.

## 실험 계약

| 항목 | 고정 내용 |
|---|---|
| 기존 기준선 | 사용자 결과 ZIP에서 검증한 TinyThermalUNet, SHA256 `9d6a84170f4012f5fbe187e169ca0235466ee2170c5019d381353bd8cd4dba5f` |
| 추가 학습 | 위 가중치에서 v2로30epoch, 옵티마이저 초기화 |
| 처음부터 학습 | 같은 구조의 무작위 가중치에서 v2로30epoch |
| 공통 조건 | seed20261119, batch16, AdamW lr0.001/weight decay0.0001, cosine schedule, 각 최대1800초 |
| 학습/선택 데이터 | v2 train480쌍/dev120쌍. train만으로 class weight를 계산하고 dev weighted CE 최소 checkpoint 선택 |
| 증강 | 기준·현재·정답에 동일한 수평/수직 뒤집기. 두 학습의 배치/증강 RNG 계획을 해시로 비교 |
| 공통 입력 | 측정 기준·현재°C 배열에서 만든 고정 asinh3채널. 실제 두께·원인·배관 마스크·무잡음 값은 입력 금지 |

| 원래 기준선 문턱 | 0.825를 별도 `baseline_original_point` 행으로 보존 |

| 최종 평가 | 문턱과 dev 비교후보를 먼저 저장한 뒤 test120/stress120쌍 평가. holdout에서 재선택 금지 |

같은 추가30epoch 비교다. 추가 학습 모델은 이미 v1의30epoch를 경험했으므로 **총 학습 비용이 같은 비교는 아니다.** 한 seed 실험이며 반복 seed에 대한 안정성은 후속 검증이다. 같은 GPU·버전·학습 step·배치 계획이 아니면 정상 비교를 거절한다. 시간이 부족해30epoch를 끝내지 못하면 미완료로 남긴다.

## 정합 품질 검사

`assess_registration(reference,current,policy)`는 **두 측정 영상만** 받는다. 실제 생성 이동량·정답 마스크·기전 이름을 주입하지 않는다. 국소 구역의 phase correlation/ECC로 잔여 평행 이동을 추정하고 공간 합의를 검사한다. 추정 이동이0.5픽셀을 넘거나 텍스처·추정 신뢰도가 부족하면 보류한다. 이미지를 강제로 정렬해 덮어쓰지 않는다.

이 검사는 제한된 평행 이동 검사다. 회전·원근·변형·가림·센서 보정까지 검증한 일반 정합기가 아니다. 보정 드리프트는 별도 calibration ID·센서 교정 기록 등이 필요하다. 모델 출력이 없다고 입력 품질이 정상이라고 간주하지 않는다.

품질 검사 설계에는 독립 procedural fixture와 v2 train만 사용한다. 노트북은 frozen policy를 그대로 실행하며 dev/test/stress로 정책을 조절하지 않는다. 보류된 입력은 모델 추론 전에 차단하고 **세 모델·규칙에 같은 통과 집합**을 적용한다.

결과에는 다음을 모두 기록한다.

- 전체 입력 수·통과 수·보류 수와 통과율.
- 통과 영상의 IoU·오경보·프레임 검출률.
- 보류된 양성 영상 수와 **전체 양성을 분모로 한 검출률**.
- 별도 정합 오류 fixture의 보류율. 보정 드리프트 fixture는 정합 정답으로 취급하지 않음.

보류를 정상/안전 판정이나 필수 검사 취소로 바꾸면 안 된다. 현재 품질 정책이 반사 변화까지 많이 보류한다면 조건부 IoU만으로 개선을 선언하지 않는다. 고정 합격 조건에 test/stress 통과율90% 이상, 정합 오류 보류율95% 이상을 포함했다. 조건 미달은 결과로 남기며 문턱을 몰래 완화하지 않는다.

## 실행 순서

1. Colab에서 **새 노트북 업로드**로 `MAEK_v2_threeway_train_compare.ipynb`를 연다. 기존 v1 노트북의 셀에 ZIP만 바꾸지 않는다.
2. 런타임 유형을 GPU로 바꾼다. 첫 셀은 GPU가 없으면 중단한다.
3. 업로드 셀에서 **`MAEK_v2_threeway_bundle.zip` 한 개**를 선택한다. 데이터·기준 가중치·코드·출처/검증 메타데이터가 모두 포함됐다. 업로드 후 전체 SHA256/파일 해시를 검사한다.
4. 데이터 독립 검증과 train 정합 품질 검사를 실행한다. 통과율과 보류 사유를 확인한다.
5. 추가 학습 셀, 처음부터 학습 셀을 차례로 실행한다. 서로 다른 출력 폴더에 저장하며 기존 폴더를 덮어쓰지 않는다.
6. 비교 셀을 실행한다. dev에서 문턱을 고정한 뒤 test/stress 결과와 품질 통계를 출력한다.
7. 마지막 결과 다운로드 셀을 실행한다. 오류나 시간초과 이후에도 이 셀은 실행할 수 있다.

작업 폴더가 이미 있다는 오류가 나오면 결과를 먼저 다운로드하고 새 런타임에서 다시 시작한다. 같은 출력 폴더를 지우거나 낮은 점수 때문에 반복 실행하지 않는다. 런타임이 끊어지면 임시 파일이 사라질 수 있으므로 완료 후 즉시 결과를 저장한다.

## 결과 다운로드와 해석

결과 파일명은 **`MAEK_v2_threeway_results.zip`**이다. 자동 다운로드가 막히면 Colab 왼쪽 파일 패널에서 `/content/MAEK_v2_threeway_results.zip`을 우클릭해 다운로드한다. 로컬의 `D:/obsd/Projects/hackerton/outputs/maek-c/`에 보관하고 경로를 알려주면 해시·학습·비교 결과를 재검산할 수 있다.

| 파일 | 내용 |
|---|---|
| `baseline/best.pt` | 변경하지 않은 v1 기준선 |
| `runs/finetune/`, `runs/scratch/` | 각각의 best.pt, history.csv, training.json; 중단 시 interrupted.pt |
| `quality/train-registration.json` | 학습 세트에서의 품질 검사 통계 |
| `comparison/selected.json`, `dev-sweep.csv` | dev 문턱 탐색과 고정된 비교후보 |
| `comparison/summary.csv`, `metrics.json` | 세 모델·규칙·기존 원래 문턱, 통과 입력 성능과 전체 입력 통계 |
| `comparison/registration-*.json` | 영상별 정합 검사·보류 근거 |
| `comparison/registration-quality-fixtures.json` | 정합 오류·보정 드리프트 별도 fixture 진단 |
| `result_manifest.json` | 전체 파일 해시와 complete 표시 |

`complete=true`는 두 학습과 비교가 정상 완료됐다는 뜻이다. 후보가 기준선을 이겼다는 뜻은 `improvement_supported`와 세부 조건으로 별도 판단한다. 어떤 결과도 자동 배포하지 않는다. OFF가 선택되거나 통과 집합에 양성/무변화 지원이 없으면 유효한 검출기로 채택하지 않는다.

v2 dev/test/stress에는 감육 양성 관측 지원이 없다. 따라서 이 실험의 높은 IoU를 감육·균열 정확도로 표현할 수 없다. 이번 노트북은 CPU 지연·메모리/Jetson 성능 벤치마크도 실행하지 않는다.

## 배포 전 확인된 정합 검사 한계

TRAIN 전용 진단에서 유효 입력은 349/480(72.708%) 통과했고, 정합 오류는 96/96 보류했다. 유효 입력 통과율 목표 90%는 미달이다. 반사 변화 입력은 18/96만 통과하여 어려운 영상이 제외되는 선택 편향이 크다. 따라서 통과 영상의 IoU와 함께 전체 입력 대비 탐지율 및 보류율을 읽어야 한다.

학습 세트 안에서 16타일 후보를 한 번 비교했지만 유효 입력 통과가 214/480으로 악화되어 원래 정책으로 복원했다. dev/test/stress로 정책을 조정하지 않았다. 현재 검사는 전역 평행이동 검사이며 일부 영역의 국부 이동, 비강체 변형, 모든 교정 드리프트를 보장하지 않는다. 이 노트북은 비교 실험을 실행할 수 있게 준비한 것이며 현장 적용을 승인하지 않는다.
