# MAEK 목적에 맞춘 열화상 학습·증강 설계

작성일: 2026-11-08. 상태: 역할 명세에 종속된 하위 학습 설계 제안. 이번 작업에서 데이터 생성·학습·배포는 실행하지 않았다.

**우선 적용 문서는 [열화상 역할 명세](thermal-role-contract.md)다.** MAEK의 목적은 가스 배관의 균열·감육 등 누출/파손 위험 구간을 조기에 선별하고 검사 자원을 집중하는 것이다. 아래의 기존 wet/보온 손상/steam 개선안은 보조 시나리오의 관측 모델 실험이며 전체 목표의 학습 계획을 대신하지 않는다. 역할에 맞는 데이터·정밀검사 정답·물리 위치 연결을 확인한 뒤 해당 실험을 실행한다.

**데이터 감사 갱신:** [현재 적합성 판정](thermal-data-fitness.md)에 따라 v3 열화상과 기존 두 가중치는 가스 배관 균열·감육 학습/검증 근거에서 제외한다. 원본은 보조 실험 재현용으로 보존한다. 새 192조건768영상은 관측가능성 민감도 자료이며 학습 준비 완료가 아니다. 아래 6회 학습 계획을 자동 실행하지 않는다.

## 목적과 검토 방식

MAEK는 RGB·열화상·설비 이력으로 검사 후보를 선정하고 정밀검사 결과와 운전 조건으로 정비 우선순위를 정한다. 열화상은 그중 관측 근거를 공급하는 역할이다. 현재 열화상 라벨로 학습 가능한 것은 wet_insulation, insulation_damage, steam_leak이며, 가스 배관 균열·감육 검사 대상 선정의 정답은 별도로 필요하다.

[Matt Pocock의 grill-me](https://github.com/mattpocock/skills/blob/main/skills/productivity/grill-me/SKILL.md)와 그 본체 [grilling](https://github.com/mattpocock/skills/blob/main/skills/productivity/grilling/SKILL.md)를 읽어 적용했다. 원본은 사용자와 의사결정을 순차적으로 확인하는 인터뷰다. 이번에는 사용자의 “스스로” 요청에 맞춰 사실은 코드·실험으로 확인하고 설계 선택은 권고안으로 답했다. 사용자 확인을 받은 것처럼 취급하지 않는다. 전역 스킬 설치는 하지 않았다.

## 권장 제품 구조

1. 입력: 원본 방사측정 열화상, 시간·설비/배관 ID, 가능한 경우 정합된 RGB와 촬영 조건.
2. 입력 품질: 비정상 값, 포화, 흐림·가림, 배관 위치 신뢰도를 기록한다. 초기에는 설명 가능한 규칙과 품질 표시로 시작하며 학습 분류기를 추가하는 것은 라벨이 있을 때 한다. 반사 여부를 완벽하게 판정한다고 가정하지 않는다.
3. 열적 관측: 소형 분할 모델로 위치·범위·대비·판독 상태를 제공한다. 기존 YOLO11n-seg의 세 이상 클래스는 보온/증기 하위 시나리오의 기준선이다. 가스 배관은 적합한 관측 라벨을 먼저 확보하며 점수를 균열 확률로 부르지 않는다.
4. 구간 집계: 원본 좌표로 복원한 마스크를 실제 배관 구간에 연결하고 중복 후보를 합친다. 위치 불확실성도 보존한다. 추적은 영상·위치 대응 데이터가 있을 때 추가한다. 짧은 증기 징후를 일률적인 연속 프레임 규칙으로 제거하지 않는다.
5. 후속 검사: 열적 관측·RGB·설비 이력을 결합한 별도 모듈이 적합한 정밀검사 후보를 고른다. wet→PEC는 일부 보온 배관 경로다. 열화상 미검출 때문에 기존 고위험/필수 검사를 제외하지 않는다.
6. 건전성 판단: 확인된 두께·결함 크기와 재질·하중·운전 이력으로 별도 평가한다. 현재는 검사 필요성과 측정값을 설명하는 수준으로 두며 근거 없는 파손 확률·발생 시점은 출력하지 않는다.

배관 ROI는 실제 추론 때 구할 수 있어야 한다. 학습 정답 pipe mask를 모델 입력으로 사용하지 않는다. 최초 비교는 전체 영상에서 가능한 전처리로 수행한다. 이후 배관 탐지/정합 기반 ROI를 도입하면 ROI 누락까지 포함한 전체 경로 성능을 다시 측정한다. 증기 영역은 배관 밖으로 뻗으므로 배관 마스크로 예측을 강제 절단하지 않는다.

## 입력 표현 비교: 구조를 먼저 크게 바꾸지 않는다

| 표현 | 구성 | 검증하는 가설 / 비용 |
|---|---|---|
| A: 기존 기준 | -40~200℃ → 8bit gray → 동일한 3채널 | 기존 결과 재현용 기준 |
| B: 온도 정보 보존 | 원본 겉보기 온도를 float32로 보존하고 고정된 단조 압축 함수로 정규화한 값을 3채널 복제 | 전처리의 양자화·범위 손실 감소. 압축 중심/척도는 train만으로 정하고 검증 때 고정 |
| C: 온도+다중 크기 잔차 | 채널1=B, 채널2=좁은 주변 대비 잔차, 채널3=넓은 주변 대비 잔차 | 배관 전체 온도 차이와 약한 국부 이상을 함께 제공. 전처리 비용과 경계/반사 강조 부작용을 측정 |

B의 초기 함수 후보는 `asinh((T-c)/s)`이며 c와 s 및 최종 수치 범위는 학습 데이터·장비 조건만으로 정한다. 표준 YOLO 데이터 로더의 8bit 이미지 읽기/255 나눗셈을 그대로 통과시키면 B/C가 구현되지 않는다. float 입력 로더·정규화·모델 추론을 일치시키고 실샘플을 거친 tensor 범위와 채널 순서를 검증한다. 의미 채널을 RGB/BGR 변환으로 뒤바꾸지 않는다.

C의 초기 잔차는 GT 없는 영상 기반 강건한 지역 배경 추정으로 만든다. 작은/큰 윈도 크기는 학습셋의 픽셀 크기를 기준으로 정한다. 배관 축 잔차는 실제 추론 ROI가 확보된 뒤 별도 후보로 평가한다. 입력 변환 자체가 기존 사전학습 색 분포와 달라지므로 동일 COCO 초기화에서 비교하되, 초기 층 조정 효과는 별도 기록한다.

A와 B 차이는 양자화와 압축 함수를 함께 바꾸는 표현 패키지 비교다. 승리하더라도 두 요인의 개별 인과 효과로 해석하지 않는다. 필요할 때만 동일 범위 float 후보를 추가해 분리한다. C와 B는 잔차 채널의 추가 가치 비교다. 16bit PNG 저장 때 이미 포화된 값은 float로 되돌려도 복원되지 않는다. 새 합성 데이터는 저장 이전 float 온도도 보존하고 센서 포화와 학습 입력 포화를 구분한다.

## 데이터 증강: 온도 생성 단계에서 일관되게 바꾼다

기존 생성기에도 반사·이음매·줄무늬·클램프·고온 배경이 있다. 이를 처음 추가한다고 설명하지 않고, 분포·동시 출현·실제 실패 사례의 유사 조건을 보강한다.

| 보강 축 | 생성/수집 방법 | 방지할 오류 |
|---|---|---|
| 약한 wet | 함수율·보온 두께·유체/외기 온도·바람을 함께 변화시키고 낮은 대비 구간을 더 자주 추출 | 밝고 큰 wet만 학습하는 현상 |
| 작은 steam | 누설 조건·촬영 거리·시야·바람·센서 해상도에 맞춰 작은 plume 생성 | 단순 축소로 물리적 크기나 라벨이 깨지는 현상 |
| 어려운 정상 | 반사, 이음매, 클램프, 줄무늬, 고온 배경과 평범한 정상 모두 확보 | 결함 민감도를 올릴 때 정상 경보가 늘어나는 현상 |
| 같은 배경의 대조쌍 | 동일 설비·배경·센서 조건에서 결함 유무/강도만 바꾼 쌍을 생성 | 배경, 노출 범위, 외장 종류로 결함을 추측하는 현상 |
| 위치·형상 | 합리적인 물 고임 위치, 다양한 시점·부분 가림·다수 배관, 경계의 부드러움 다양화 | 특정 화면 위치나 하나의 도형에 의존 |
| 외장·환경 | 외장 방사율, 카메라 방사율 설정 오차, 하늘/지면 반사, 일사·바람을 일관된 조건으로 생성 | 서로 양립하지 않는 물리 조건을 무작위로 섞는 오류 |
| 센서 | 측정에 근거한 NETD, 보정 잔차, 흐림·해상도 저하·포화·결측을 모사 | 이상 픽셀을 결함으로 오인하거나 불가능한 미세 신호를 요구 |

외장 재질과 방사율, 증기 상태와 압력·온도, 시점과 하늘 반사, 바람과 plume 방향은 연계해서 생성한다. 방향 편향을 없앤다고 무조건 상하를 50:50으로 뒤집지 않는다. 현장 조건에 따른 물리적 편향은 남기되 학습 때 본 조합에만 의존하는지 시험한다.

기하 변환은 원본 온도·마스크·위치 메타데이터에 동기 적용하고, 의미 채널은 변환된 온도에서 다시 계산한다. 처음에는 기존의 작은 이동·스케일과 가능한 좌우 반전을 유지한다. HSV/임의 밝기 변화, MixUp, Mosaic, 의미 채널 뒤섞기는 초기 비교에서 끈다. 원본 합성기를 통한 여러 배관 장면을 우선한다. 설정을 0으로 해도 설치된 추가 증강 라이브러리가 변환을 수행할 수 있으므로 실제 loader 출력과 설치 버전을 확인한다. 이는 일반 RGB 권장값과 달리 온도 의미를 보존하려는 MAEK 설계 선택이다. [Ultralytics 증강 설명](https://docs.ultralytics.com/guides/yolo-data-augmentation/)

학습에서 존재 GT가 있는 약한 결함은 유지한다. 노이즈 수준 아래라 정보가 없는 사례까지 무조건 찾아야 한다는 목표는 두지 않는다. 신호 대비·크기·포화별 성능을 따로 보고, 보류는 전체 입력 중 비율과 후속 재검사량에 포함한다. 테스트에서 어려운 표본을 제외해서 수치를 올리지 않는다.

## 데이터 구성과 분할

기존 보온/증기 하위 실험의 보강 샘플링 제안은 정상 40%, wet 중심 30%, steam 중심 20%, damage 중심 10%다. **가스 배관 전체 학습 데이터에 적용할 비율이 아니다.** 정상 중 절반은 평범한 정상, 절반은 어려운 정상으로 시작한다. 이는 최적 비율이나 현장 발생률이 아니라 시험할 출발점이다. 다중 결함은 생성 주유형으로 샘플링 바구니를 정하되 모든 실제 라벨을 보존한다. 정상 원본에서 증강 후 결함이 생기는 변환은 허용하지 않는다.

- D0: 기존 학습 분포/증강 정책. D1: 위의 실패 원인 중심 분포와 물리적으로 타당한 보강. 모든 표현에 같은 D0/D1 manifest를 쓴다.
- 분할은 증강 전 `base_scene_id` 또는 실제 배관 구간·촬영 세션 단위로 한다. 같은 배경의 결함 유무 대조쌍과 모든 증강본은 같은 분할에 둔다. 단순 파일명/프레임 단위 분할은 피한다. [그룹 기반 검증 설명](https://scikit-learn.org/stable/modules/cross_validation.html)
- train → 모델/체크포인트 선택 → 임계값 교정 → 마지막 확인의 역할을 명시한다. 소량일 때 앞의 두 선택 용도는 개발셋을 공유할 수 있지만 최종 확인셋은 공유하지 않는다.
- 이미 본 기존 val/shifted 및 27조합 확인셋은 회귀 진단 자료다. 그 안의 실패 유형은 개발에 사용할 수 있지만 해당 데이터를 최종 독립 성능으로 재보고하지 않는다.
- 새 최종 합성 확인셋은 seed뿐 아니라 외장×환경×시점×결함 크기의 미관측 조합을 포함한다. 같은 생성기라는 한계는 남는다. 실측셋은 별도로 필요하다.
- 증강은 학습에만 확률적으로 적용한다. 평가 입력·전처리는 고정한다. 확인용 메타데이터를 추론 입력에 몰래 넣지 않는다.

도메인 랜덤화는 합성과 실측의 차이를 줄이기 위한 접근이다. 관련 연구의 성공은 다른 시각 작업에서 나온 것으로, MAEK 현장 성능을 보장하지 않는다. [원 논문](https://arxiv.org/abs/1703.06907)

## 유한 실험 계획

선행 조건: 역할 명세 단계 1의 대상/센서/관측 라벨 적합성과 단계 2의 출력·위치 계약을 확인한다. 기존 증기 데이터만 있으면 아래 실험의 결과도 그 하위 도메인에 한정한다. 새로운 가스 배관 라벨의 종류와 분포는 그 확인 후 정하며 기존 3클래스 이름을 균열로 치환하지 않는다.

1. 로컬에서 새 데이터/입력 변환을 소량 생성해 단위·채널·포화·마스크 동기화·그룹 중복을 확인한다. 실패 사례의 원본 온도와 A/B/C tensor를 비교한다.
2. Colab GPU에서 A/B/C × D0/D1 = 6개를 비교한다. 기존 30epoch checkpoint는 보존하고 같은 사전학습 가중치에서 시작한다. 첫 비교는 동일 batch16, 해상도320, optimizer·학습률 schedule, 고정 2,000 optimizer update를 제안한다. 데이터 수가 달라도 epoch 수가 아닌 update와 본 샘플 수를 맞춘다. 이 예산은 개발 제안이며 최적값이 아니다.
3. 첫 정상 실행으로 시간·VRAM을 확인한 뒤 나머지 실행 전에 회차별 timeout과 총 Colab 사용 상한을 동결한다. 장비가 바뀌면 비용 비교를 분리한다. 실패 재시도는 원인 수정 후 후보당 1회까지, OOM 때 특정 후보만 batch를 바꿔 동일 조건인 것처럼 비교하지 않는다.
4. 기준을 포함한 상위 2설정에 seed 2개씩 추가하여 총 10회까지 학습한다. 추가 seed 전에 최종 확인셋은 열지 않는다. 지표가 나빠서 즉흥적으로 epoch를 늘리지 않는다. 후속 가설은 별도 실험으로 기록한다.
5. 개발셋에서 정한 checkpoint와 클래스 임계값을 고정하고 새 확인셋을 한 번 평가한다. 기존 무회귀 gate와 paired CI를 적용하며 최악 조건 wet/steam 성능도 보고한다. 새 목표가 기존 gate와 충돌하면 결과를 본 뒤 gate를 바꾸지 않고 다음 실험 전에 목적을 다시 정한다.
6. CPU 전처리+모델+후처리와 전체 구간 집계 경로를 따로 측정한다. 현 기준인 3회 모두 p95≤200ms를 확인하고 RSS를 기록한다. 잔차 전처리·다중 crop·추적 비용도 포함한다. Jetson은 실제 장비 확보 전까지 미측정으로 둔다.

정확한 학습률·데이터 장수·시간 상한은 현장 목표/Colab 실측에 따라 실행 프로토콜에서 고정해야 한다. 이번 문서는 학습 시작 명령이나 완료된 실험이 아니다. 기존 30epoch와 새 fixed-update 결과는 학습 예산이 다르므로 정확도 비교는 가능해도 동일 예산 개선이라고 주장하지 않는다.

## MAEK 완성을 판단할 지표와 필요한 실측

기존 class-image recall, 정상 FA, FP/image, pooled IoU, paired CI는 하위 관측 과제의 회귀 지표로 유지한다. 최종 판정은 [역할 명세의 성공 기준](thermal-role-contract.md)에 따라 같은 검사 예산에서 위험 기반+RGB 대비 열화상 추가의 실제 균열·감육 선별 이득을 비교한다. 추가로 구간별 recall, 중복 제거 후 알림 수, 판독 보류율, 구간 집계까지의 지연을 측정한다. 검사 비용이 다르면 K개 검사 대신 비용/작업시간 예산으로 비교한다. 촬영 길이/면적 보정 없이 이미지당 오경보를 km당 오경보로 환산하지 않는다. 손실 가중치나 중요도 가중 점수는 운영 근거가 생기기 전 임의의 확률로 만들지 않는다.

실측 데이터에는 `site_id, pipe_id, segment_id, timestamp, camera/settings, thermal_raw, rgb_alignment, inspected_region, inspection_method, measured_thickness, crack_location/size, insulation_opening_result, operating_conditions, label_provenance`를 담는다. 두께와 균열은 각 검사 범위/감도/불확실성과 함께 저장한다. 후속 검사 대상으로 선택된 양성 의심 지점만 모으면 검증 편향이 생기므로 열화상 미검출·정상 후보도 표본 조사한다. 반복 검사를 통해 변화율을 측정하고 파손 시점 예측은 사건·추적 기간·미발생 추적 정보가 쌓인 뒤 검토한다.

최종 목표는 열화상 점수 하나를 높이는 것이 아니라 제한된 검사 자원에서 중요한 감육·균열을 더 잘 찾아내는 연결을 입증하는 것이다. 현재 완료 가능한 범위는 선별 모델의 개선 실험과 검사 후보 연결 시제품이며, 현장 감육·균열 예측 성능과 Jetson 실측은 별도 미완료 항목이다.
